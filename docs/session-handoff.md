## 2. Key technical facts you will need
**Solver/generator (`src/prison.js`).** Exact search over (configuration digits, dark region). Digit order: cameras, guards, toggles (doors/mirrors), dogs, lights. `who` indices: items by digit index, panels = `dg.length + j`, "wait" = first light index. `actions()` wraps `actions0()` and applies `sweep()` for searchlights; panels via `panelApply`; wired items have no own actions (`wiredOf`). Level ASCII: `# . S E`, `^>v<` cameras, `0-3` searchlights (wall cells), `a-d` guards, `e-h` dogs (rail in `meta.dogs`), `X/x` doors, `/ \` mirrors, `p-r` panels (links in `meta.panels`), `G` glass. `phasesDP` counts the separate walks a level needs (used by `regen-low.js` to avoid one-phase "set everything, then run" levels).
**Level pipeline.** `tools/level-specs.js` (the ramp; `Cells` block is `grid` 6 entries, `phases` re-keyed, TOTAL 176) → `gen-levels.js` (slow for late blocks, split ranges over processes) → `regen-low.js` → `build-levels.js` (re-solves every level, writes `play/levels.js`) → `build-single.js`. Any rule change ⇒ rebuild levels and run the full play-test.
**Renumbering/migration.** `PROGRESS_V = 2`; `OLD_TO_NEW = {1:1, 3:2, 7:3, 10:4, 12:5, 14:6}`; `newIdOf(o) = o >= 16 ? o-9 : (OLD_TO_NEW[o] || 0)`; local one-time migration via key `pb_pv`; `mergeProgress` output carries `v`; server (`worker/routes/blindeye.js`): `clean()` adds `v` (default 1), `merge()` lets the higher version win and ignores older posts. Intro cards: `INTROS = {1:'cam',7:'guard',37:'door',57:'mirror',77:'all',97:'dog',117:'light',137:'panel',157:'glass'}`. Anonymous stats recorded before 2026-10-07 for levels ≥16 use the old ids.
**Rendering.** Oblique canvas, painter's order by rows, beams as polygons. The normal floor/camera beam is skipped for rays in `chainWho`; the mirror overlay pass draws before the "wires" overlay.
**Portal build.** `tools/build-single.js --target crazygames [--out dir]` replaces text tokens `@TARGET@ @SITE_PATH@ @SITE_RE@ @POM_EN@ @POM_FA@ @OWNER@ @YEAR@ <!--@PORTAL_META@-->` and `'__BUILD__'`; in-game `PORTAL` flag; `.web-only` CSS hides account/ranking/stats/report UI; `FREE_HINTS`; `gateOn`; dead server code stays but is inert (`api()` returns offline; `ONLINE`/`STATS_HOST` false). `tools/package-portal.js` builds, runs the safety checks (forbidden strings `luckylion|pixels of the mist|zenith|dubiko|eqbalhozhabr`, unreplaced tokens, any http(s) address, owner name present) and zips `index.html` at the root into `releases/crazygames/` (git-ignored). **Do not mention the owner's other game, company or website in code that reaches the portal bundle** (a comment once leaked the other game's name and the packager caught it).
**Backend.** Cloudflare Worker + D1 (binding `DB`), cookie session `pom_session`, lazy `CREATE TABLE IF NOT EXISTS`, e-mail via Resend. Local e2e runs the real handlers over `node:sqlite` (`tools/e2e-account.js`, needs `SITE_DIR`).
**Tests.** `play-test.js` (real mouse clicks through every level, checks moves === par, plus layout-stability, guard-control and star-gate checks), `e2e-account.js`, `portal-test.js` (iframe sizes 907x510, 1216x684, 1077x606, 821x462, 1366x768, 1920x1080, 1536x864, 1280x720, 800x450, 1080x607 + 390x844/844x390 phones, zero outside requests, keyboard play, portal rules). e2e picks its "exposing action" level dynamically (the fixed index broke when levels were renumbered).
**Media.** `tools/media/make-covers.js` (canvas drawing from the game's own sprites at exact 4x; `COVERS` config per cover; title kept out of the top-left label zone) and `tools/media/record-preview.js` (virtual clock overriding rAF/performance.now/Date.now/timers/Math.random; bot plays levels `1,4,7,37,57,97,117` with real clicks; 560 frames at 30 fps; ffmpeg recipes from the playbook; first 0.5 s is the cover). Outputs are in the **old container only** (`releases/crazygames/…`); regenerate with `OWNER_NAME="…" node tools/package-portal.js` then the two media scripts.

2. Site repo: branch from `origin/main`; copy `play/prisonbreak.html` to `public/blind-eye/index.html` **inserting `<meta name="robots" content="noindex, nofollow">` right after the viewport meta**; include any `worker/` changes; push.
3. Open a PR (GitHub MCP), wait ~2.5 min for the green **"Workers Builds: luckylion-website"** check (get_check_runs), squash-merge (owner pre-approved merging/pushing), then poll `curl https://luckylion.games/blind-eye/` for the new marker until deployed (~2.5 min after merge).

5. Report to the owner in Persian; send files with SendUserFile when asked.
Gotchas: never `sleep` ≥ a long foreground time (blocked); use an until-loop with `timeout`. `pkill -f` can kill your own shell — use `pgrep` then `kill <pid>`. `build-single.js` paths must use `path.resolve`. If a stash pop conflicts with generated html, check out the generated files first.
