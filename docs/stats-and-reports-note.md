# نوت پیاده‌سازی: «آمار ناشناس» و «گزارش مرحله»

برای وقتی که همین دو قابلیت را در بازی دیگری می‌خواهیم. در Blind Eye ساخته و آزمایش شده و روی `luckylion.games` زنده است. این نوت یک‌جا می‌گوید چه ساخته‌ایم، چرا این‌طور، چطور به بازی دیگر ببریمش و به چه چیزهایی باید دقت کرد.

> مرجع کد (کپی‌پذیر):
> - سرور: `luckylion-website/worker/routes/blindeye-stats.js`، مهاجرت `migrations/0004_blind_eye_stats.sql`
> - صفحهٔ آمار: `luckylion-website/public/blind-eye-stats/index.html`
> - کلاینت: `PrisonBreak/play/index.html`، بخش `statistics and reports` (دنبال `function track(` بگردید)
> - تست: `PrisonBreak/tools/e2e-account.js`، بخش «7. anonymous statistics…»
> - الگوی اولیه (Dubiko): `worker/routes/dubiko.js` و `public/dubiko-stats/`

---

## ۱. هدف و اصل‌ها

**هدف:** مرحله‌ها را از روی بازی واقعی تنظیم کنیم، نه حدس. دو منبع داده:
1. **آمار ناشناس**: بازیکن‌ها چه می‌کنند (شروع، بردن، گرفتار شدن، رها کردن، راهنما…).
2. **گزارش مرحله**: بازیکن‌ها خودشان چه می‌گویند (خیلی سخت، خیلی آسان، گیج‌کننده، خراب است، دیگر + یک جملهٔ اختیاری).

**اصل‌ها (نشکنید):**
- **ناشناس واقعی**: فقط یک شناسهٔ تصادفی که مرورگر برای خودش نگه می‌دارد. هرگز به حساب، ایمیل یا IP وصل نشود و ذخیره نشود. در Blind Eye حتی وقتی بازیکن وارد حساب است، آمار به حسابش وصل نمی‌شود.
- **بازیکن بتواند خاموشش کند** (کلید در تنظیمات) و با خاموش بودن **هیچ** رویدادی نرود.
- **بازی را کند نکند و خراب نکند**: ارسال دسته‌ای، بی‌صدا، بدون انتظار؛ خطای شبکه نادیده گرفته شود.
- **سرور هیچ ورودی را باور نمی‌کند**: فهرست سفید رویداد و ویژگی، سقف اندازه و تعداد، محدودکردن اعداد.
- **آمار برای تنظیم مرحله است، نه رقابت**: هر کسی می‌تواند رویداد ساختگی بفرستد. هرگز جایزه یا جدول رتبه را به آن وصل نکنید.

## ۲. معماری در یک نگاه

```
مرورگر ──(دسته‌ای، text/plain)──▶ POST /api/<game>/event   ─▶ جدول <game>_events
مرورگر ──(JSON، همان origin)────▶ POST /api/<game>/report  ─▶ جدول <game>_reports
تو (با کلید) ───────────────────▶ GET  /api/<game>/stats   ─▶ جمع‌بندی SQL
تو ─▶ /<game>-stats/  (صفحهٔ خصوصی، noindex): جدول مرحله‌ها + پرچم‌ها + یادداشت‌ها + Copy JSON
```

Worker و D1 همان‌هایی‌اند که سایت دارد (`wrangler.jsonc`: binding به نام `DB`). برای بازی جدید فقط یک فایل مسیر + دو جدول + یک صفحه اضافه می‌شود.

## ۳. رویدادها (قرارداد بین کلاینت و سرور)

بدنهٔ `POST /api/<game>/event` (با `Content-Type: text/plain` تا preflight CORS لازم نشود):

```json
{ "a": "<aid: 16 hex>", "s": "<sid: 16 hex>", "v": "<build>", "l": "en|fa", "p": 1, "x": 0,
  "ev": [ { "e": "level_win", "t": 1760000000000, "n": 12, "ms": 41000, "moves": 7, "par": 6,
            "hints": 0, "lost": 1, "undo": 2, "stars": 2 } ] }
```
- `a` = شناسهٔ دائمی مرورگر (`localStorage`)، `s` = شناسهٔ همین بار باز کردن صفحه، `v` = نسخهٔ ساخت، `p` = صفحهٔ لمسی، `x` = ترافیک تست.
- رویدادهای Blind Eye: `session_start`, `level_start` (`again`), `level_win`, `level_caught`, `level_leave`, `mistake` (`k` = نوع مقصر), `hint`, `ad` (`k` = دلیل, `ok`).
- برای بازی دیگر **فقط فهرست `EVENTS` و ویژگی‌های مجاز را عوض کنید**؛ شکل بقیه ثابت می‌ماند. هر رویداد: `e` نام، `t` زمان، `n` شمارهٔ مرحله، و اعداد کوچک.

**ستون‌های جدول** (`blind_eye_events`): `rcv` (زمان دریافت), `ts` (زمان رویداد، نزدیک `rcv` بریده می‌شود), `aid`, `sid`, `ev`, `lvl`, `ms`, `moves`, `par`, `props` (JSON کوچک ≤ 200 نویسه), `build`, `lang`, `phone`, `test`.

**گزارش** (`POST /api/<game>/report`، JSON):
```json
{ "a": "<aid>", "n": 12, "k": "too_hard|too_easy|confusing|bug|other", "note": "حداکثر ۲۰۰ حرف", "v": "<build>", "l": "en", "x": 0 }
```
جدول `blind_eye_reports`: `rcv, aid, lvl, kind, note, build, lang, test`.

## ۴. کلاینت (الگوی کد)

```js
const STATS_HOST = /^(www\.)?luckylion\.games$/.test(location.hostname) || TEST_HOST;   // TEST_HOST = localhost
let aid = store.get('x_aid', null); if (!aid) { aid = rid(8); store.set('x_aid', aid); }  // rid(8) = 16 hex
const sid = rid(8); let evq = [], flushT = null;

function track(e, extra) {
  if (!settings.stats || !STATS_HOST) return;                       // خاموش = هیچ‌چیز
  evq.push(Object.assign({ e, t: Date.now() }, extra));
  if (evq.length >= 15) flushEvents(); else if (!flushT) flushT = setTimeout(() => flushEvents(), 8000);
}
function flushEvents(beacon) {
  clearTimeout(flushT); flushT = null; if (!evq.length) return;
  const body = JSON.stringify({ a: aid, s: sid, v: BUILD, l: settings.lang, p: matchMedia('(pointer:coarse)').matches ? 1 : 0,
                                x: TEST_HOST ? 1 : 0, ev: evq.splice(0, 40) });
  try {
    if (beacon && navigator.sendBeacon) navigator.sendBeacon(URL, new Blob([body], { type: 'text/plain' }));
    else fetch(URL, { method: 'POST', body, keepalive: true, headers: { 'Content-Type': 'text/plain' } }).catch(() => {});
  } catch (e) {}
}
addEventListener('pagehide', () => { leaveLevel(); flushEvents(true); });
document.addEventListener('visibilitychange', () => { if (document.hidden) flushEvents(true); });
```

**جاهای وصل‌کردن (Blind Eye):**
| رویداد | کجا |
|---|---|
| `level_start` | آخر `load(level)`؛ `again` = همان مرحلهٔ قبلی |
| `level_leave` | اول `load()` و `toMenu()` و `pagehide`، فقط اگر مرحله نه برده شده نه گرفتار |
| `level_win` / `level_caught` | تابع برد / گرفتار شدن؛ بعدش `lvl.done = true` تا «رها کردن» دوباره شمرده نشود |
| `mistake` / `hint` / `ad` | جایی که آژیر شروع می‌شود / راهنما داده می‌شود / صفحهٔ تبلیغ بسته می‌شود |
| `session_start` | یک بار موقع بار شدن، با `first` برای بازدید اول |

- زمان‌ها را **در کلاینت سقف بزنید** (مثلاً ۳۰ دقیقه) تا مرحله‌ای که تب باز مانده میانگین را خراب نکند.
- `BUILD`: در `tools/build-single.js` به‌صورت تاریخ + هش گیت جایگزین می‌شود (`'__BUILD__'`). برای مقایسهٔ نسخه‌ها لازم است.

**گزارش مرحله (رابط):** دکمهٔ «گزارش مرحله» در منوی توقف، صفحهٔ بردن و صفحهٔ گرفتار شدن؛ یک صفحه با پنج دکمهٔ انتخابی (فقط یکی) + جعبهٔ متن ≤ ۲۰۰ حرف + ارسال/انصراف. بدون انتخاب نوع، ارسال نمی‌شود. بعد از ارسال «ممنون» و بسته‌شدن خودکار. گزارش، عمل صریح بازیکن است، پس **با خاموش بودن آمار هم کار می‌کند**.

**تنظیمات:** یک کلید «آمار ناشناس» (پیش‌فرض روشن) با یک خط توضیح («نتیجهٔ مرحله‌ها و تعداد لمس‌ها با یک شناسهٔ تصادفی؛ بدون نام و ایمیل»). حریم خصوصی را در صفحهٔ حساب هم یک خط بنویسید.

## ۵. سرور (چک‌لیست)

- مسیرها در `worker/index.js` ثبت شوند: `POST event`, `POST report`, `GET stats`.
- **جدول‌ها اولین بار خودشان ساخته می‌شوند** (`CREATE TABLE IF NOT EXISTS` با یک `ready` در سطح ماژول)، پس لازم نیست کسی مهاجرت دستی بزند. فایل مهاجرت هم همان دستورها را دارد.
- `event`: بدنه ≤ ۱۶ کیلوبایت، حداکثر ۴۰ رویداد در هر درخواست، شناسه‌ها با `^[0-9a-f]{8,32}$`، رویداد فقط از فهرست سفید، ویژگی‌ها فقط از فهرست سفید و فقط عدد/بولی/رشتهٔ کوتاه، `ts` اگر بیش از یک روز از الان دور بود با `rcv` عوض می‌شود، اعداد با `int(v, lo, hi)` بریده می‌شوند. پاسخ `204`.
- `report`: **همان origin** (در غیر این صورت `403`)، بدنه ≤ ۲ کیلوبایت، نوع از فهرست سفید، یادداشت بدون نویسه‌های کنترلی و ≤ ۲۰۰، **حداکثر ۲۰ گزارش در روز به‌ازای هر شناسه** (`429`).
- `stats`: هدر `Authorization: Bearer <کلید>` با مقایسهٔ زمان‌ثابت (`constantTimeEqual`)؛ بدون کلید روی سرور `404`، کلید غلط `401`. کلید: `BLIND_EYE_STATS_KEY` یا اگر نبود همان `DUBIKO_STATS_KEY`. **برای بازی جدید** یک نام تازه (`<GAME>_STATS_KEY`) تعریف کنید و در Cloudflare به‌عنوان Secret بگذارید، یا همان کلید مشترک را دوباره استفاده کنید.
- پرسمان‌ها (`SUM(ev = 'x')` و `json_extract(props, '$.k')` در SQLite/D1 کار می‌کنند): برای هر مرحله بازیکن‌ها (`COUNT(DISTINCT aid)`), شروع‌ها, حل‌کننده‌ها, بردها, گرفتاری, رها کردن, هشدار, راهنما, میانگین زمان و حرکت, **حرکت/par**, میانگین ستاره و Undo؛ گزارش‌ها به‌ازای مرحله و نوع؛ ۱۰۰ یادداشت آخر.
- **ترافیک تست جدا:** `test = 1` برای localhost؛ همهٔ پرسمان‌ها `test = ?` دارند و صفحه کلید «ترافیک تست» دارد.

## ۶. صفحهٔ آمار خصوصی

`public/<game>-stats/index.html` (`<meta name="robots" content="noindex, nofollow">`). کلید را می‌گیرد (در `sessionStorage` می‌ماند)، `GET stats` را صدا می‌زند و نشان می‌دهد: KPI کلی، جدول مرحله‌ها (قابل مرتب‌سازی)، **پرچم‌ها**، گزارش‌ها و یادداشت‌ها، دکمهٔ «Copy JSON».

**پرچم‌ها** (بعد از حداقل ۴ بازیکن در آن مرحله؛ عددها را به بازی خودتان بسپارید):
- کم‌حل‌شده: درصد حل‌کننده‌ها < ۶۰٪
- زیاد گرفتار: گرفتاری/شروع > ۰٫۳۵
- بازیکن‌ها رها می‌کنند: رها کردن/شروع > ۰٫۵
- راهنمای زیاد: راهنما/شروع > ۰٫۸
- آژیر/اشتباه زیاد: > ۲٫۵ به‌ازای هر شروع
- خیلی بالاتر از par: حرکت/par > ۱٫۸
- شاید زیادی آسان: حل ≥ ۹۵٪، بدون اشتباه و راهنما، زمان < ۲۰ ثانیه، حرکت/par < ۱٫۱۵
- گزارش‌های بازیکن‌ها (مثلاً «۲ × خیلی سخت»)

## ۷. تست (حتماً بنویسید)

`tools/e2e-account.js` سرور واقعی Worker را با یک SQLite درون‌حافظه به‌جای D1 و مرورگر واقعی اجرا می‌کند. بررسی‌های آمار:
- یک بازی واقعی (آژیر، راهنما، بردن در par، رها کردن) ⇒ رویدادهای درست در جدول؛
- همه با `test = 1` و بدون هیچ ایمیل در داده؛
- با کلید خاموش هیچ رویدادی نمی‌رود؛
- گزارش از صفحه‌های واقعی؛ بدون انتخاب نوع پیام می‌دهد؛ سقف روزانه (`429`)؛ نوع ناشناخته `400`؛
- آمار بدون کلید `404`، با کلید غلط `401`، با کلید درست داده؛ و صفحهٔ آمار داده را نشان می‌دهد.

**دام‌هایی که در تست خوردیم:**
- چند صفحه در یک تست همه رویداد می‌فرستند ⇒ شمارش را با **`sid` همان صفحه** فیلتر کنید.
- `ctx.request` در Playwright **کوکی‌ها را با خود مرورگر تست شریک است**؛ ورود یک کاربر دیگر با آن، نشست صفحه را عوض می‌کند. برای «غریبه» یک `request.newContext()` جدا بسازید.
- ورودِ لینک یک‌بار مصرف را با دکمه تأیید کنید، نه با GET (مربوط به حساب کاربری است ولی همین تست را می‌شکند).

## ۸. چیزهایی که می‌ماند

- **جعل:** رویداد و گزارش ساختگی ممکن است (سدهای اندازه/تعداد/فهرست سفید فقط جلوی زیاده‌روی را می‌گیرند). برای رقابت جدی باید راه‌حل را روی سرور بازپخش کرد.
- **هرزنامه:** سقف گزارش فقط به‌ازای شناسه است؛ کسی که شناسهٔ تازه بسازد دور می‌زند. اگر لازم شد، نرخ‌گیری با Cloudflare اضافه کنید.
- **اندازهٔ جدول:** رویدادها همیشه جمع می‌شوند. برای مدت طولانی، یک کار زمان‌بندی‌شده بنویسید که رویدادهای قدیمی‌تر از ۹۰ روز را پاک کند (`DELETE … WHERE rcv < ?`).
- **نگهداری شناسه‌ها:** پاک کردن داده‌های مرورگر شناسه را عوض می‌کند و همان بازیکن «جدید» حساب می‌شود.

## ۹. چک‌لیست انتقال به بازی دیگر

1. در بازی: `settings.stats` (پیش‌فرض روشن) + کلید در تنظیمات + یک خط حریم خصوصی؛ `aid/sid/track/flushEvents` را کپی کنید؛ `STATS_HOST` را با دامنهٔ خودتان بسازید.
2. رویدادها را به نقطه‌های واقعی بازی وصل کنید (جدول بالا) و `level_leave` را فراموش نکنید.
3. رابط گزارش: دکمه در منوی توقف/برد/باخت + صفحهٔ انتخاب نوع + یادداشت.
4. سرور: `blindeye-stats.js` را به `<game>-stats.js` کپی کنید، فهرست `EVENTS` و پیشوند جدول‌ها (`<game>_events`, `<game>_reports`) و مسیرها را عوض کنید، در `worker/index.js` ثبت کنید.
5. کلید: Secret جدید یا استفاده از کلید مشترک.
6. صفحهٔ آمار: `public/<game>-stats/` را کپی کنید؛ پرچم‌ها را با معیارهای بازی خودتان عوض کنید.
7. تست‌ها: بخش ۷ را برای بازی جدید بنویسید و قبل از ادغام اجرا کنید.
8. بعد از ادغام: صفحهٔ آمار و مسیرها را روی سایت زنده بررسی کنید (`/api/<game>/stats` بدون کلید باید `401` بدهد).
